## Hypothesis

The vite-react-ssg integration in blog-v2 exhibits a recurrent failure pattern across 3+ failure classes (`confabulation`, `phantom_limb`, `source_amnesia`) within a single session date. This suggests a structural gap in how vite-react-ssg's build + render lifecycle integrates with our Vite config, rather than isolated bugs.

## Evidence

**Failure sequence (same session, 2026-06-10):**

1. **confabulation** — `dist/index.html` does not exist when rendering starts
   - Assumed file exists; did not (hook runs too late in lifecycle)
   - Fix: moved copy to pre-build phase (build-setup.mjs)
   - Status: RESOLVED

2. **phantom_limb** — `dist/.vite/ssr-manifest.json` not found by rendering phase
   - Hook writes file, but rendering subprocess cannot access it
   - Suggests subprocess context isolation (separate working dir, file descriptors)
   - Status: ACTIVE (manifest still missing at render time)

3. **source_amnesia** — `collectAssets()` receives non-iterable `files` parameter
   - Lost reference to expected data structure (array vs object)
   - Occurs AFTER rendering completes, during static-loader-data generation
   - Status: ACTIVE (data contract mismatch)

## Root Cause Hypothesis

vite-react-ssg is an all-in-one SSG tool with an integrated build + render lifecycle. Our approach (Vite hooks) assumes the hook-based setup aligns with vite-react-ssg's expectations. Evidence suggests:

1. **Lifecycle mismatch**: vite-react-ssg's rendering phase runs in an isolated context (subprocess, separate working directory) where Vite's hook writes are not visible.
2. **Data contract gap**: vite-react-ssg expects a specific StaticDataLoader export shape / manifest structure that our build setup does not provide.
3. **Integration immaturity**: The vite-react-ssg library may not support our build orchestration pattern (pre-build setup + Vite hooks). We may need custom build wrapper or library fork.

## Proposed Experiment

**Goal**: Determine whether vite-react-ssg integration requires build orchestration refactor or is a blocker in the library itself.

**Steps**:

1. **Investigate vite-react-ssg expectations**:
   - Read vite-react-ssg source: collectAssets function signature and manifest contract
   - Check if vite-react-ssg has documented manifest path config or built-in discovery
   - Verify StaticDataLoader export shape against what collectAssets expects

2. **Test pre-build manifest setup**:
   - Create manifest in build-setup.mjs BEFORE vite-react-ssg runs
   - Verify rendering phase finds it (resolves phantom_limb)
   - Check if collectAssets receives iterable files parameter (resolves source_amnesia)

3. **Determine integration pattern**:
   - If pre-build setup works: vite-react-ssg expects manifest pre-existence; update build pipeline
   - If it fails: vite-react-ssg may require direct library config or subprocess context fix
   - If vite-react-ssg source reveals incompatibility: fork or replace library

4. **Proof of concept**:
   - Build should complete with `tsc && vite-react-ssg build`
   - Verify dist/ output contains pages + proper manifest
   - Verify static loader data generation succeeds

## Expected Outcome

- **Success**: vite-react-ssg builds successfully to dist/; blog-v2 can ship with SSG enabled
- **Partial fix**: pre-build manifest resolves 2 failures but source_amnesia persists (deeper data contract issue)
- **Blocker**: vite-react-ssg library fundamentally incompatible with our setup; need fork or replacement (explore alternatives: Astro SSG, vanilla Vite + custom SSR, Next.js static export)

## Annie Phase 2 Request

Investigate and resolve vite-react-ssg integration via the experiment steps above. Priority: determine if this is a fixable setup issue or a library limitation. If library blocker, surface alternatives (Astro, Next.js static export) and trade-offs (features, bundle size, ecosystem support).
